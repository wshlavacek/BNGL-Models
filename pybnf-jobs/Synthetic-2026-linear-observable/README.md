# Synthetic-2026-linear-observable — a coupled `(scale, offset)` pair on a linear-Gaussian family

**Not a published model, not a benchmark, and not scored against anything.** A purpose-built
fixture for the lanl/PyBNF#572 evaluation (PyBNF **ADR-0123**), which could not measure the case
#572 is actually about because no slug in the Grein subset-I corpus has one.

#572 proposes profiling an observable's `scale` and `offset` out of the search by variable
projection: stack `Phi = [s, 1]`, solve `c* = (Phi^T W Phi)^-1 Phi^T W d`, score the projection
residual. That is a **linear least-squares** identity. Every coupled `(scale, offset)` pair in the
corpus — `Borghans`, `Elowitz`, `Schwen` — scores on a **log** residual, where it does not hold,
and the two slugs where it does hold (`Weber`, `Brannmark`) carry no offset at all. So the
construction's own domain was empty, and "the corpus has no instances" is a fact about
Benchmark-Models-PEtab rather than about the feature. This directory supplies the instance.

## The problem

`A -> B -> 0` with `A(0) = 1`, `B(0) = 0` — two rate constants, one observed state with a
rise-and-fall shape, so the simulated column `s(theta)` genuinely changes **shape** with theta and
not only amplitude. The observable is exactly `y = scale * B + offset`, scored with an ordinary
additive Gaussian.

```
truth:  k1 = 0.8   k2 = 0.25   scale = 3.0   offset = 1.5   sigma = 0.05
```

Five free parameters, of which **two are the coupled pair** — 40 % of the search, comparable to the
33 % `Schwen` carries. `scale`, `offset` and `sigma` are deliberately **absent from the SBML**: they
live only in the conf's observable formula and noise model, exactly as they do in the imported PEtab
slugs.

`experiment1.exp` is 27 points generated by `make_data.py` from the **closed form**
`B(t) = k1/(k2-k1) * (exp(-k1 t) - exp(-k2 t))`, not from a PyBNF simulation. That is the fixture's
own correctness test: if the SBML did not encode that ODE, the profile at the truth would not come
back at `scale = 3` / `offset = 1.5`. It does — `3.019` / `1.501`.

## Two properties to know before reading any result off this fixture

> **`offset` is a `uniform_var` on the real line, not a positive `loguniform_var`.** On a
> linear-scale family the least-squares optimum for an intercept need not be positive, and a
> positive-only declaration quietly turns the profile into a bounded search — the very thing being
> measured. The corpus's own offsets are all `loguniform`, which is a PEtab-import artefact rather
> than a modelling choice, and it matters: see the negative-`scale` finding below.

> **There are TWO global optima.** Swapping `k1` and `k2` multiplies `B` by `k2/k1`, which a free
> `scale` absorbs exactly — verified to `2.2e-16` by `make_data.py`. So `k1 = 0.25, k2 = 0.8,
> scale = 9.6` is the same curve, and a run reporting it has **not** failed. Ordinary
> identifiability structure, kept rather than engineered away.

## What it measured (ADR-0123)

Run with the corpus's tools:

```bash
cd ~/Code/BNGL-Models/pybnf-jobs
uv run --project ~/Code/PyBNF --extra tests python \
  Grein-2026-benchmark-subset-I/tools/linear_profile.py Synthetic-2026-linear-observable \
  --params scale,offset -n 80 --seed 11 --noise-profiling
```

**The landscape does not collapse.** With `scale`, `offset` and sigma all profiled, 80 box draws
give a profiled objective spanning `[-36.40, -1.19]` with IQR **20.9** — against `Borghans`'s
`[-167.15, -165.98]` and IQR **0.081** under the same treatment. Eighteen of 80 draws (22 %) sit on
the flat line `-1.194629`, against 46 of 76 (61 %) on `Borghans`. The truth stays 62 units below
the flat line. So the landscape-deletion result in ADR-0123 is a **log-family** phenomenon and does
not transfer, which is exactly what this fixture existed to find out.

**And the closed form is exactly right.** With `--closed-form` (and sigma *searched*, so `W` is the
same matrix on both sides), #572's variable projection agrees with the numeric conditional optimum
to **1.5e-14 relative** at every point where both can reach it — 53 of 80.

**The other 27 are the finding.** There, variable projection returns a **negative `scale`** and
scores a median **14.5 objective units better**. The numeric profile cannot follow it, because
`scale` is declared `loguniform` and its sampling space is strictly positive. A negative scale means
"the model predicts the mirror image of the data", and the projection reaches it because it is
**unconstrained by construction**: it does not know the parameter has a declared support.

That is a design decision an implementation has to make on purpose — clamp, refuse, or accept a
sign flip in a quantity the user declared positive — and not one to fall into. The 16 rows with a
negative *offset* are not this: `offset` is declared on the real line, both methods reach it, and
they agree.

## Files

| file | what |
|---|---|
| `model_linear_observable.xml` | SBML L2V4, 2 species, 2 reactions, `k1`/`k2` only |
| `linear_observable.conf` | edition-2 job, `gaussian` noise, `observable: y, formula: B*scale + offset` |
| `experiment1.exp` | 27 points from the closed form + N(0, 0.05) |
| `make_data.py` | the generator; `--write` regenerates the data and `truth.json` |
| `truth.json` | the generating vector, in `linear_profile.py --point` format |

No `nominal_check.json`, `jstar.txt` or `score.py`: there is no paper, no published optimum and no
benchmark scale here. `truth.json` is the only reference point, and it is one the fixture made up.
